## R4 三种合成方式（commit 7f7684f3）

需求（用户澄清后重定义）：A4 与 PPT 统一三种合成方式 —— ① 翻页式 paged（单页居中+按钮/方向键，A4 也改成翻页交互）② 网页式 flow（现状保留零改动）③ 标准页 standard（新增，固定页尺寸瀑布式排布，PDF 型，打印一页一张）。
核心修复：正文章节原本"一章一张纸"超页撑长 → paged/standard 四模板内嵌 `bkSplitProse` 浏览器端自动拆页。

- 模板：新建 a4_standard/ppt_standard；a4_book 改翻页（bk-stage/bk-nav/键盘/目录 href 锚点定位所在纸页），保留 R3 class 结构与 BK 标记；ppt_book 加拆页 JS（拆页脚本先于翻页脚本，slides 在拆页后采集）；flow 两模板零改动（git diff 空）
- 拆页算法：按 .bk-prose 块级子元素填充固定页高，表格按行拆（thead 复制到续表，首行即超则整表下移），单个超高不可拆块留本页，续页 cloneNode 无章头无 id（锚点留首页）；翻页式下非激活页 display:none 无法测量 → prepare/restore 临时 display:flex+visibility:hidden

- 验收：R4 自动化 28/28（含 playwright 实测：a4 长文+60 行大表拆 9 页、ppt 拆 17 片、零溢出、表格行/段落零丢失、翻页/计数/目录跳转正常、standard 模式下 R3 编排全生效）；回归 27+21+14+25 全过；tsc + npm build 通过

## 教训

1. **测试脚本也是污染源**：_bk_phase3_test.py 的简易 md 渲染写坏了 DB 快照 → 结构性修法是"保存时重算、不信任存量"，而非清洗数据打补丁
2. **断言别裸匹配类名**：产物 `<style>` 里保留 CSS 规则，`"bk-toc" in out` 会误判，须匹配 `class="bk-slide bk-toc"`
3. srcdoc 转义的文档不能直接喂 React `srcDoc` 属性（属性赋值不做 HTML 反转义）→ 拆出 `_build_embed_docs`（原文）与 `_build_embed_srcdocs`（转义）两层
