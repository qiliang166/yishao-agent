## 第八章 系统配置 — 8.2 全局配置

> **所属手册**：后台管理说明（管理员）

全局配置是系统的 AI 引擎管理中心。管理员在此管理 AI 服务提供商连接、7 个工作阶段的提示词模板、以及 PPT 底层核心提示词。

**进入方式**：左侧导航栏 →「⚙ 全局配置」。页面包含两个标签页：「模型设置」和「默认提示词」。

**核心机制**：全局配置中的提示词作为工厂种子数据。新建项目时自动复制，已有项目不受后续修改影响。

---

### 功能概述

**是什么**：管理 4 类 AI 提供商、7 列栏目提示词模板、5 类核心提示词。所有 Stage 的 AI 生成行为均由此处配置决定。

### 界面布局

**在哪里**：左侧导航栏 →「⚙ 全局配置」。

| 标签页 | 子标签 | 功能 |
|------|------|------|
| 模型设置 | — | LLM / TTS / ASR / 图片生成 四类提供商管理 |
| 默认提示词 | 栏目配置 | 7 列提示词/SKILL 模板 + 设计规则文件 |
| 默认提示词 | 核心配置 | PPT 底层提示词，5 类别筛选，每页 30 条 |

---

### 一、模型提供商管理

#### 功能概述

**是什么**：配置 AI 服务商的连接信息（名称/密钥/地址/模型列表）。配置成功后，模型自动出现在各 Stage 的选择器中。

#### 界面布局

**在哪里**：「全局配置」→「模型设置」标签页。页面分为 4 个区域，每区域对应一类提供商，底部为配置表格（名称 / API Key / Base URL / 模型列表 / 状态 / 操作按钮）。

| 提供商类型 | 添加按钮 | 模型列表示例 | 下游使用者 |
|-----------|---------|-------------|-----------|
| LLM | + 添加 LLM 提供商 | deepseek-chat, deepseek-reasoner | Stage 1-4 全部文本生成 |
| TTS 语音 | + 添加 TTS 提供商 | cosyvoice-v3-flash, cosyvoice-v3-plus | Stage 4b 语音合成 |
| ASR 识别 | + 添加 ASR 提供商 | fun-asr, qwen3-asr-flash | Stage 1a 语音转文字 |
| 图片生成 | + 添加图片生成提供商 | wanx-v1 | 课件插图 |

#### 操作步骤

##### 添加提供商

1. 切换到「模型设置」标签页
2. 在对应提供商区域点击添加按钮（如「+ 添加 LLM 提供商」）
3. 在弹出的对话框中填写以下字段：

| 字段 | 说明 | 示例 |
|------|------|------|
| 名称 | 服务商标识，用于 Stage 选择器中显示 | DeepSeek、阿里通义 |
| API Key | 服务商颁发的密钥 | sk-xxxxxxxx |
| Base URL | API 端点地址 | https://api.deepseek.com/v1 |
| 模型列表 | 可用模型名称，逗号分隔 | deepseek-chat, deepseek-reasoner |

4. 点击「保存」→ 配置写入数据库
5. 点击「测试」→ 验证连接 → 成功显示「连接成功 (N 个模型可用)」

##### 编辑提供商

1. 在表格中找到目标行
2. 点击「编辑」按钮 → 弹出编辑对话框（预填现有值）
3. 修改字段 → 点击「保存」

##### 删除提供商

1. 在表格中找到目标行
2. 点击「删除」按钮（红色）→ 确认后移除

#### 参数说明

**四类提供商配置**：

| 类型 | Base URL 示例 | 模型列表示例 | 下游使用者 |
|------|-------------|-------------|-----------|
| LLM | https://api.deepseek.com/v1 | deepseek-chat, deepseek-reasoner | Stage 1-4 全部文本生成 |
| TTS 语音 | https://dashscope.aliyuncs.com/api/v1 | cosyvoice-v3-flash, cosyvoice-v3-plus | Stage 4b 语音合成 |
| ASR 识别 | https://dashscope.aliyuncs.com | fun-asr, qwen3-asr-flash | Stage 1a 语音转文字 |
| 图片生成 | https://dashscope.aliyuncs.com/compatible-mode/v1 | wanx-v1 | 课件插图 |

#### 提示与注意事项

| 类型 | 内容 |
|------|------|
| 📌 注意 | 状态列显示「已连接」（绿色）或「未配置」（灰色）。仅已连接的提供商出现在 Stage 模型选择器中 |
| 💡 技巧 | TTS/ASR/图片生成提供商可勾选「设为默认提供商」，Stage 页面自动选中 |
| ⚠️ 警告 | API Key 为敏感信息，输入框显示为密码模式（圆点遮蔽），不可在页面明文查看 |
| 💡 技巧 | 模型列表支持逗号分隔多个模型名，系统会自动去空格；模型名需与服务商实际提供的模型名完全一致 |

#### 上下游功能

- **上游**：全局设置（8.1 品牌/安全/许可证）
- **下游**：各 Stage 的模型选择器、AI 生成调用

### 二、栏目配置

#### 功能概述

**是什么**：7 个栏目（col1-col7）对应 7 个工作阶段，每栏含提示词（定义 AI 角色行为）和 SKILL（定义输出格式模板）。新建项目时自动复制到项目中使用，已有项目不受后续修改影响。

#### 界面布局

**在哪里**：「全局配置」→「默认提示词」→「栏目配置」标签。页面显示 7 个栏目卡片，每个卡片可展开。卡片标题格式为「colN — 栏目名称」，右侧显示「展开/收起」箭头。

#### 操作步骤

1. 切换到「默认提示词」→「栏目配置」
2. 点击目标栏目卡片 → 展开编辑区
3. 编辑「提示词」和「SKILL 输出格式」文本框
4. （仅 col3/col4/col5）编辑设计规则文件
5. 点击「保存」→ 数据写入数据库

#### 参数说明

**7 列完整清单**：

| 栏目 | 子配置（数量） | 对应 Stage | 提示词作用 | 设计规则 |
|------|-------------|-----------|-----------|---------|
| col1 素材输入 | 素材整理（1个） | Stage 1a/b/c | 定义 AI 整理原始素材的角色行为 | 无 |
| col2 文档生成 | 标准文档(sop) / 分析文档(dao) / 综合文档(yanxi)（3个） | Stage 2a/b/c | 定义三种文档类型的 AI 生成风格 | 无 |
| col3 文档课件 | 文档课件配置（1个） | Stage 3a | 定义 A4 文档课件的生成指令 | **有** |
| col4 分析PPT | 分析PPT配置（1个） | Stage 3b | 定义分析型 PPT 的生成指令 | **有** |
| col5 综合PPT | 综合PPT配置（1个） | Stage 3c | 定义综合型 PPT 的生成指令 | **有** |
| col6 课件演讲 | 文档演讲 / 分析演讲 / 综合演讲（3个） | Stage 4a | 定义三种演讲稿的 AI 生成风格 | 无 |
| col7 语音合成 | 标准播报 / 对话 / 自定义（3个） | Stage 4b | 定义语音合成的角色口吻和风格 | 无 |

**设计规则文件**（col3/col4/col5 独有）：

| 操作 | 说明 |
|------|------|
| 查看 | 展开栏目后显示文件列表（文件名 / 状态 / 大小） |
| 编辑 | 点击「编辑」→ 内联编辑器（最低 260px 高度）→ 点击「保存文件」 |
| 状态 | 「已自定义」（绿色）或「默认」（灰色） |

#### 提示与注意事项

| 类型 | 内容 |
|------|------|
| 📌 注意 | 设计规则文件是「当前栏目独立副本」，修改 col3 的设计规则不影响 col4 或 col5 |
| 💡 技巧 | col2 三个子配置分工明确——标准文档(sop)偏结构规范，分析文档(dao)偏方法论深度，综合文档(yanxi)偏广度覆盖 |
| 💡 技巧 | col7 的字段名为「角色提示词」而非「提示词」，体现其定义角色口吻的用途（不同于内容生成提示词） |
| ⚠️ 警告 | 修改栏目提示词后，仅**新建项目**使用新版本。已有项目在项目级「栏目配置」中保留复制时的版本，不受影响 |

#### 上下游功能

- **上游**：模型提供商（所选模型必须在模型设置中已配置）
- **下游**：各 Stage 的 AI 生成行为、新建项目时的提示词复制

### 三、核心提示词配置

#### 功能概述

**是什么**：PPT 生成流程中的底层提示词模块（33 项以上），按 5 个类别组织。每张幻灯片生成时，`build_slide_prompt()` 函数按类型/功能/布局自动组装对应模块，注入 AI 生成请求。修改后仅新建项目使用新版本。

#### 界面布局

**在哪里**：「全局配置」→「默认提示词」→「核心配置」标签。

| 区域 | 控件 |
|------|------|
| 类别筛选栏 | 按钮组：全部 / 根级别 / 通用规则 / 按类型 / 按功能 / 按布局 |
| 提示词列表 | 每页 30 条，每项显示：文件名 + 「编辑」按钮 |
| 编辑区 | 点击「编辑」后展开，含文本框（最低 200px）+ 「保存」按钮 |
| 分页栏 | 底部分页控件（上一页 / 页码 / 下一页） |

#### 操作步骤

1. 切换到「默认提示词」→「核心配置」
2. 点击类别筛选按钮，过滤目标类别
3. 找到目标项，点击「编辑」→ 展开编辑区（最低 200px 高度）
4. 修改提示词内容 → 点击「保存」
5. 使用底部分页控件翻页（每页 30 条）

#### 参数说明

**5 个类别**：

| 类别 | 键名 | 项数 | 加载时机 | 说明 |
|------|------|------|---------|------|
| 根级别 | root | 若干 | 基础定义 | 全局性基础规则 |
| 通用规则 | always | 10 | 每张幻灯片始终加载 | 不可跳过的核心约束 |
| 按类型 | by_type | 4 | 根据幻灯片类型条件加载 | 卡片 / 角色 / 装饰 / 插图 |
| 按功能 | by_feature | 1 | 含图表时加载 | 图表语言与决策规则 |
| 按布局 | by_layout | 若干 | 根据布局类型加载 | 全幅 / 双栏 / 三栏 / 网格等 |

**通用规则类（always）— 10 个必加载项**：

| 文件名 | 作用 |
|--------|------|
| identity.md | AI 身份角色和整体行为准则 |
| iron-laws.md | 不可违反的铁律规则（最高优先级） |
| colors.md | 颜色使用规则 |
| color-semantics.md | 颜色语义（正/负面色使用场景） |
| structure.md | 幻灯片结构规范 |
| richness.md | 视觉丰富度指标 |
| typography.md | 排版层级规范 |
| consistency.md | 跨页一致性规则 |
| checklist.md | 质量自检清单（22-23 项） |
| format-spec.md | HTML/CSS 格式规范 |

**按类型类（by_type）— 4 个条件加载项**：

| 文件名 | 触发条件 |
|--------|---------|
| cards.md | 幻灯片类型为卡片型 |
| card-roles.md | 需区分卡片角色时 |
| decoration.md | 需装饰元素时 |
| illustration.md | 需配图/插图时 |

**按功能类（by_feature）— 1 个**：

| 文件名 | 触发条件 |
|--------|---------|
| charts.md | 幻灯片含图表/数据内容 |

**核心提示词组装逻辑**（`build_slide_prompt()` 函数执行顺序）：

```
① 始终注入 always/ 下全部 10 个文件（identity → format-spec）
② 如果幻灯片类型为卡片 → 注入 by_type/cards.md + card-roles.md
③ 如果需要装饰元素 → 注入 by_type/decoration.md + illustration.md
④ 如果含图表/数据 → 注入 by_feature/charts.md
⑤ 根据布局类型 → 注入 by_layout/{layout}.md
```

所有注入的提示词拼接为一个完整 Prompt，发送给 LLM 生成幻灯片 HTML。

#### 提示与注意事项

| 类型 | 内容 |
|------|------|
| ⚠️ 警告 | 核心提示词影响**所有** PPT 的生成质量，修改前建议备份原内容（复制到本地文件保存） |
| 📌 注意 | 修改仅影响**新建项目**，现有项目在项目级「核心配置」中保留复制时的原版本 |
| 💡 技巧 | 提示词文件按加载顺序编号（always 类 1-10），修改时注意保持顺序，后加载的规则会覆盖前加载的同类规则 |
| 💡 技巧 | iron-laws.md 为最高优先级铁律，任何其他规则与铁律冲突时以铁律为准 |

#### 上下游功能

- **上游**：全局设置（8.1）、栏目配置（col3/col4/col5 的设计规则文件）
- **下游**：Stage 5 PPT 生成、模板管理（第九章 VI 系统注入）、最终课件视觉质量
